The Problem

AI has no memory. Teams have drift.

Every AI conversation starts from zero context. Every new session risks contradicting decisions the last one made. And every teammate who wasn't in the room when a choice was made will build against their own assumption of what the product should be.

Across Ehoro Village's first 14 sessions, this produced real damage: schema drift, regressions, conflicting naming conventions, design decisions that contradicted the product's core philosophy. The codebase grew but coherence didn't.

The manifesto was born out of necessity. It's the document that makes every session start from the same shared model — whether the session is with Claude, with ChatGPT, with Gemini, or with a human teammate who missed last week.

The Rules

16 rules that every AI reads before writing code.

These aren't suggestions. They're hard constraints forged from real regressions. Every rule exists because something broke without it.

From the manifesto — Rules for AI Assistants

01 Vanilla JS only. No frameworks, no build tools, no npm. The entire app is one HTML file.
02 Do not refactor CSS. Add new styles at the end. The existing CSS has been carefully built over many sessions.
03 Companion, not game. Do not add mechanics that demand active attention.
05 Test against actual DB schema. ALWAYS verify column names. The schema has been patched many times.
06 RPC over direct mutations. All game state changes go through SECURITY DEFINER RPCs.
09 When you finish your session, append a dated entry to the Session Log. What you changed, what SQL ran, what broke.
13 Always DROP old function overloads before recreating RPCs. PostgREST 400s when it can't resolve ambiguity.
16 When asked to redesign visually, propose first — do not build. Session 21 proved full CSS rewrites break the product's feel.

Architecture

One global object. Every render reads from it.

The client architecture is intentionally simple: a single global S object holds all state. Every RPC writes to it. Every UI render reads from it. No state management library, no framework indirection — just a flat, inspectable source of truth that any AI or human can trace through in seconds.

The S Object — client-side single source of truth

// All client state in one flat object let S = { // Auth user: null, isGuest: true, // Game data — fetched from Supabase spirits: [], emblems: { cafe_bean: 0, wild_essence: 0, ... }, buildings: [], expeditions: [], // Streaming state playing: false, currentStream: 'ehoro', eggT: 0, EGG_SEC: 3600, }; // Data flow: Action → RPC → loadUserData() → updateAllUI()

This pattern means any AI session can understand the entire data flow in one read. No dependency graphs, no context-splitting, no hidden state. The manifesto documents the shape of S in full so every session starts with the same mental model of what the app's state looks like.

What It Prevents

The failure mode the manifesto kills.

Session 21 — The revert

A full CSS rewrite was attempted. The owner reviewed it and reverted.

Session 21 attempted a glassmorphism redesign — a wholesale CSS rewrite replacing all existing variables. The result looked visually worse than what 20 prior sessions had carefully built up. The entire session was discarded. The V2.9 file was restored as the working baseline.

This produced two new rules (15 and 16): CSS fixes go at the bottom as a patch block. When asked to redesign visually, propose first — do not build. The manifesto learned from the failure and made it unrepeatable.

Session 18 — The 400 errors

PostgREST couldn't resolve which function to call.

A prior session changed an RPC's signature without dropping the old one. PostgreSQL kept both as overloads. PostgREST threw 400 errors because it couldn't disambiguate. This spawned Rule 13: always DROP old function overloads before recreating RPCs.

Every rule in the manifesto has a story like these. The document doesn't just tell AI what to do — it tells it why, with a specific failure as the receipt. An AI that understands the reason behind a constraint doesn't accidentally route around it.
